# useful-scripts

The repository's own machinery: the code that maintains and checks the analysis, as opposed
to the code that performs it. Every Python script here has a **dual interface** — a
programmatic API and a CLI — so it is useful both as a library and standalone. Invoke as
`.venv/bin/python AI-internal/useful-scripts/<name>.py`, or `bash …/<name>.sh`.

Note the two interpreters: these run under `.venv` (the repository's tooling), while the
analysis itself runs under `environment/chapenv` (the pinned, published environment).
`verify_model_determinism.sh` and `candidate_fork_sweep.py` are the exceptions that call
into the second, because what they run is the analysis.

| Script | What it does | Skill |
|---|---|---|
| `node.py` | Create, inspect, promote and rebuild claim-tree nodes, enforcing the alternatives/sub-analyses semantics so they cannot drift by hand | `/node` |
| `check_invariants.py` | The deterministic checks: tree, provenance, hashes, plots, seeds, claims, combos, freeze, git, and values crossing steps by hand | `/validate invariants` |
| `check_freeze_defence.py` | Put eleven situations to the frozen phase-E set's two defences — the node script that writes it and the `freeze` invariant that checks it — on throwaway copies, and record what each did. Four of them corrupt the frozen manifest, which is why none of them runs against the live tree. Writes to `AI-generated/validation/` | — |
| `run_cleanroom.sh` | The clean-room harness: clone the repository at HEAD into a scratch directory, build `environment/chapenv` from `environment/lock.txt`, run `analysis/run.sh` from cold, and record git's own diff. The clone's index *is* the archive, so there is no second copy of the results to keep in step. Run it detached from the session, and under `caffeinate -ims` — batch 18's clean-room died with its session, and batch 27's elapsed time was unreadable because the host slept through it | `/validate cleanroom` |
| `cleanroom_compare.py` | Sort what the clean-room run changed into identical, path-only and numeric, and diff the reported `conclusion.json` side by side. Run from the clean-room directory after the run | `/validate cleanroom` |
| `cleanroom_tier2_drift.py` | Why batch 25's clean-room run stopped: whether every model we wrote returned the same CRPS per combination, whether the tier-2 selection rule picks the same eight pairs from a second draw of tier-1 conclusions and by what margins it decided, and what the reference's four repeats did to the noise band. Carries a self-check — its copy of the rule must reproduce the archived selection, and nothing under `tier2` means anything if it does not. Writes to `AI-generated/validation/` | — |
| `cleanroom_holdout_reproduction.py` | What a clean-room run established about the **phase-E half**: per model and per combination on both halves, the holdout distribution's reported fields archived beside the clean-room's, whether the environment was the lockfile's once ANSI colour is stripped from `uv pip freeze`, and the comparison against the frozen development figures — separating a drifted *number* from a moved *pairing*, the distinction batch 30 built into the tree. Reads the preserved artefacts, so it still answers after the clone is gone. Writes to `AI-generated/validation/` | `/validate cleanroom` |
| `cleanroom_phase_e_answer.py` | The three files `pair_holdout_development.py` writes, archived beside a clean-room run's, field by field. They existed to compare for the first time in batch 31: batch 27 exited 1 *at* that script, so they were carried unchanged out of the clone's index and its comparison called them identical. Each scalar is classified **reference-derived** or **structural** by a listed field path rather than a heuristic, so what moved with the unseeded reference is separated from what the answer asserts. Writes to `AI-generated/validation/` | `/validate cleanroom` |
| `check_selection_defence.py` | Put five situations to the recorded tier-1 order and tier-2 pairing batch 26 introduced, one of them driven by the clean-room run's own `conclusions.csv` — the data that broke batch 25. Each scenario swaps one tracked input, invokes the node script under `chapenv`, and restores from git unconditionally. Writes to `AI-generated/validation/` | — |
| `check_pairing_defence.py` | Put five situations to the frozen-pairing check batch 30 rebuilt in `pair_holdout_development.py`, one of them driven by batch 27's own preserved `conclusions.csv`. Writes to `AI-generated/validation/` | — |
| `pool_check_rewrite.py` | What batch 28's rewrite of the 51 `pool_check.json` files changed: both versions of every file flattened to their leaves, each differing key classified as a **naming** change, the added annotation, a **reconstruction** that appeared, or a **numeric** change to a value that existed before. Exits non-zero if any number moved or any row lost its reconstruction. Writes to `AI-generated/validation/` | — |
| `check_reconstruction_defence.py` | Put four states to the sweep that settles every pool row — the record batch 16 left on the headline holdout row, an already-correct file, a missing file, and a row no order of execution could reconstruct — on the live tree, restoring each afterwards and checking with git that `analysis/` is left exactly as committed. Writes to `AI-generated/validation/` | — |
| `claims.py` | Maintain and audit the claim collection; flag draft sentences with no supporting claim | `/claims` |
| `build_hierarchical_report.py` | Generate the linked static-HTML drill-down report from the tree | `/hierarchical-report` |
| `verify_model_determinism.sh` | Rule 6: run each of our models twice under **one** scratch combination — pass 1's outputs copied aside, pass 2 overwriting them in place — and compare the per-cell scores, the model listing and the fitted model. One name for both passes is deliberate: with two, the check compared a column recording the pass's own scratch name and could never pass. Writes to `AI-generated/determinism-checks/` and removes the scratch combination | — |
| `family_leaderboard.py` | What each candidate family scores **at its own main path**, in one table — the record the family fork is promoted from. An alternatives node runs one child, so no single combination holds all three families; each row is read from the combination in which that family ran with every internal fork at the child it declares, found by matching rather than named. Writes to `AI-generated/candidate-forks/<label>/` | — |
| `candidate_fork_sweep.py` | Run every non-main child of a candidate's forks on the development data, one combination each, and tabulate what they score. `--candidate`, `--base` and `--inherit-from` say which candidate is swept, which combination its main path ran under, and which one a swept row inherits from. Writes its results **into the tree** through the tree's own scripts, and only the cross-combination table to `AI-generated/candidate-forks/`. A phase-C selection aid, not the stability node | — |

`check_invariants.py` exits non-zero on any failure, so it works in a pre-commit hook or CI.
**When it fails, fix the cause — never weaken the check.**
